# 多幣預算、實際支出與現金盤點

本次新增「學習」「其他」行程類別，幣別統一提供 PHP 披索、TWD 台幣、USD 美金、VND 越南盾。行程日期不由本次改版更動。匯率由使用者手動填入，並非即時牌告或換匯建議；測試金額與匯率均為合成資料。

## 預算欄位

原本兩個固定的「全團日幣」「全團台幣」欄位改成「金額（行程預算）」與幣別選擇。選台幣即可記台灣先付的預算，不需要第二格才能統計；已付款項仍應另外記在實際花費，預算不重複列支出。

- 新資料使用 `item.budget: [{cur, amt}]`。明確的空陣列代表已清除預算。
- 讀取舊資料時，`yen` 仍為 JPY、`ntd` 仍為 TWD，絕不把舊日幣直接當披索。
- 舊項目兩格都有金額時，主金額可編輯，附加金額會顯示並保留。只有明確按「移除舊附加預算」才刪除它；儲存後轉為 budget 陣列，不再重複計入舊欄位。
- 預算總計、類別、行程卡與完整版 PDF 共用相同換算。沒填匯率時保留原幣並標示「未填匯率／已換算部分」，不宣稱完整台幣總額。
- 披索部分、台幣部分固定顯示；美金及越南盾一併顯示。只有真實舊預算含 JPY 時才顯示舊日幣部分。

## 花費及金流

`misc.kind` 分為 `expense`（或舊資料未填 kind）、`exchange`、`cashflow`。只有 expense 進入支出統計。換匯記付出／收到原幣及實收金額，成交匯率為「收到 ÷ 付出」，不自動改寫估算匯率。手續費另記花費。

`cashflow.direction` 為 in／out，供領現、補入或移出現金使用。刷卡不減手上現金；金融卡提款應記現金增加，提款費另列花費。既有無法判斷的電子支付方式會保留原文字，編輯時選「待確認」，不擅自改成現金。

VND、JPY 新輸入須為整數；PHP、USD、TWD 最多兩位小數。實際台幣帳單金額可取代該筆估算，包含明確填 0 的情況。

## 帳面現金餘額

第一次按「盤點現金」，輸入當下實際點算的各幣現金；留白代表不改該幣別，0 代表沒有。未設定的幣別顯示「未盤點」，不猜測開帳金額。

每幣在 `private/config.wallet.snapshots[cur]` 保存 `{amount, at, includedIds}`。`includedIds` 是該次盤點時已存在的 misc 文件 ID，這些金流已包含在實際點算中，不再加減。各幣可分別盤點，不影響私人資訊及其他幣別。

盤點後新增的紀錄會即時計算：

| 紀錄 | 現金效果 | 支出效果 |
| --- | --- | --- |
| 現金花費 | 扣原幣 | 列支出 |
| 刷卡花費 | 無 | 列支出 |
| 換匯 | 扣付出幣、加收到幣 | 無 |
| 現金增加／減少 | 加／扣原幣 | 無 |
| 行程預算 | 無 | 無 |

新增補登盤點前的舊帳時，勾選「已包含在目前的現金盤點」，保存 `cashIncluded: true`，避免重複扣款。系統按是否已包含於盤點判斷，不單靠日期猜測金流先後；使用者可補登旅程外的已付機票。修改／刪除盤點後紀錄會重算；盤點前既有紀錄的修改不回推實際盤點。若要記新的金流，另新增紀錄。

缺金額、付款方式待確認時，餘額標示暫不完整；負數仍顯示並提醒核對。這是依使用者紀錄計算的帳面餘額，不會自動讀取銀行、信用卡或得知口袋實際現金；有落差可重新實際盤點。

## 匯出、相容性與驗證邊界

完整 JSON 備份保留 budget、cashflow、cashIncluded、wallet snapshots 與原有私人資訊，格式仍為 `trip-content` v1，另標記 `moneyVersion: 2`。新版可匯入舊備份；舊版無法完整解讀新增預算與現金功能，請勿拿新版備份回舊版繼續記帳。未來高於 2 的 moneyVersion 會拒絕匯入。既有備份檢查器的結構通過不等於真實手機的備份已還原。

完整版 PDF 包含預算原幣／估算、現金盤點及帳面餘額、實際支出摘要與金流明細；家人版不帶金額、現金或私人資訊。沒有既有分攤資料時不輸出空分攤表。

驗證包括純函式案例（舊雙幣、清除預算、缺匯率、VND、現金／刷卡／換匯／領現、補登、編輯刪除、重新盤點、JSON 往返）、既有區段／記帳／備份測試，以及隔離 localhost 的 390×844 UI 實測。測試資料不含個人訂票、支付或旅程資訊。實際手機資料與正式網站需在合併／發布後另驗證；本次 PR 不部署。
